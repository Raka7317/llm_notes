1-PAGE REFERENCE

1What Is a Leaderboard?

Simple idea: Benchmark = the exam. Result = the score. Leaderboard = where results get published & compared.
Benchmark→Result→Leaderboard

2Formal Definition

"A public ranking and comparison table that shows how different LLMs perform on a common set of evaluations."

3Why Leaderboards Exist

  • Compare models across labs
  • Trust — 3rd-party vs self-reported
  • Guide selection without testing everything
  • Detect saturation — top scores clustering
  • Discover smaller/cheaper models

4Filtering, Not Deciding

Key idea: leaderboards narrow 100+ models to ~3–5 candidates you then test yourself.

5Benchmark Saturation

If top models cluster tightly (e.g. 92–94), the benchmark stops separating strong models — it's becoming less useful.

6Who Uses Leaderboards

AI EngineersShortlist → custom evals
Frontier LabsTrack competitive position; may delay release if not competitive
ResearchersSaturation, trends, techniques
Policy/SafetyMonitor capabilities
OSS CommunityDiscovery, visibility

7"Nano Banana" Example

A model appeared under a stealth identity on an image leaderboard, performed extremely well, then was publicly identified — leaderboards work as discovery tools for labs too.

9Type 1 — Benchmark-Specific

Single benchmark (MMLU, HumanEval, GSM8K, GPQA). Simple, but narrow.

Limit: excellent on one test ≠ best overall model.

Ex: Humanity's Last Exam (HLE).

10Type 2 — Multi-Benchmark

Combines dimensions: knowledge, reasoning, math, coding, instruction following, data analysis.

Cost/tokenLatencyOutput speedContext window

Ex: LiveBench (contamination-free), Artificial Analysis (intelligence/speed/cost/coding/speech/image/audio/hardware).

11Type 3 — Human-Preference

2 models answer→User votes better→Votes aggregate→Ranking

Ex: LM Arena — chat, coding, image, video categories.

Bias: humans favor longer/confident/well-formatted/entertaining answers — not necessarily "correct."

12Type 4 — Application-Specific

CodingAgenticSQLMedicalTool calling

Ex: Berkeley Function Calling Leaderboard — can combine multiple benchmarks while staying focused on one domain.

13Core Warning

Rule: a leaderboard score is not a prediction of real-world app performance.

14Limit 1 — Doesn't Transfer

Benchmarks = clean data, clear problems. Real apps are messy:

Ambiguous requestsMissing infoCompany dataTool failuresEdge cases

15Limit 2 — Contamination

If benchmark data leaks into training data, score gets inflated — not proof of real generalization.

16Limit 3 — Goodhart's Law

"When a measure becomes a target, it becomes less useful as a measure."

Models can get over-optimized for leaderboard-specific reward patterns instead of real capability.

17Limit 4 — Hidden Methodology

  • Which benchmarks included/excluded?
  • How are scores normalized?
  • What weight per capability?
  • How is composite computed?

18Limit 5 — Small Diffs Don't Matter

84.3 vs 84.1 ≈ noise, not meaningful superiority. Don't fixate on rank position alone.

19Limit 6 & 7

Human biasPrefers style, length, confidence over correctness
Stale/self-reportedOld versions, unverified numbers, slow updates

20How to Read a Leaderboard

Start with: "What does my app need?" — not "who is #1?"

21Step 1 — Define Constraints

App typeLatencyCostContext needsDeployment (API/on-prem)

Constraints first — an on-prem requirement can eliminate the #1 model outright.

22Step 2 — Match Leaderboard

AppLeaderboard
ChatbotHuman-preference (LM Arena)

RAGEmbedding/model leaderboards
Cost-sensitiveCost + speed oriented

23Step 3 — Read Methodology

  • What & how is scored, by whom?
  • Inference/reasoning budget used?
  • Dataset age, update frequency
  • Private test set? Saturated?
  • Confidence intervals, dataset size
  • Composite weighting per capability

24Step 4 & 5 — Shortlist & Test

  1. Filter to 3–5 candidates
  2. Run your own custom evals
  3. Best on YOUR eval = production choice

25Full Selection Funnel

100+ Models→Leaderboard Filter→3–5 Candidates→Custom Evals→Final Model

26Session Flow

Benchmarks→Leaderboards→Custom Evals→App Evals (RAG/Agent)

27Most Important Takeaway

Leaderboards are NOT a selection tool — they're a filtering tool.

Never let a leaderboard directly decide which model your application uses.
