3How the Retriever Works

Query→Embed→Search vector DB→Top-k chunks

Build: load docs → chunk → embed → store → expose retriever.

4Two Failure Modes

Miss relevant contextNeeded info exists but not retrieved → measured by recall
Retrieve noiseIrrelevant chunks distract generator → measured by precision
Trade-off: raising K usually ↑ recall but ↓ precision.

5Why Reference-Based

Need a golden reference per query to know if retrieval was correct.

Old way: label exact relevant chunks — brittle, breaks on re-chunking.
Better way: store an ideal answer per question; LLM judge breaks it into atomic claims & checks context support.

6Contextual Recall

Supported ideal-answer claims ÷ Total ideal-answer claims

Judge decomposes ideal answer into claims, checks which are covered by retrieved chunks. 1 of 2 claims → 0.5.

vs Recall@K: Recall@K needs pre-labeled chunks; contextual recall uses ideal answer + judge — resilient to re-chunking.

7Contextual Precision

Rank-aware: are useful chunks retrieved early, without noise?

Judge inspects each chunk in rank order → marks helpful/not.

Score ↑: relevant chunks near top. Score ↓: irrelevant chunks near top.

8Recall vs Precision Reading

High recall, low precisionCorrect material exists, buried in noisy context
High precision, low recallChunks look relevant but omit key facts

9Failure Mode → Metric → Fix

SymptomMetricFix
Answer not groundedLow recallBetter retrieval/chunking/embeddings, careful K↑
Relevant buried in noiseLow precisionBetter ranking/filter, K↓, reranker

10Creating the Golden Dataset

Min: question + ideal answer. Four ways to build it:

Manual writingLLM-generated Synthetic-data toolMine prod logs

This course: LLM-assisted + manual QC, small batches, human-sounding questions.

11Component-Level Workflow

  1. Prepare documents
  2. Build retriever (chunk, embed, index)
  3. Create goldens (Q + ideal answer)
  4. Retrieve context per golden Q
  5. Judge claims (recall + precision)
  6. Analyze & iterate

12Running the Evaluation

For every golden row: send Q → retriever, collect chunks, score recall+precision, aggregate.

Don't stop at the average — inspect low-scoring cases to find if chunk size, embeddings, K, filters, or source docs need fixing.

13Eval Pseudocode

for row in golden_dataset:
  ctx = retriever.retrieve(row.q, k=K)
  recall = contextual_recall(
    q, row.ideal_answer, ctx)
  precision = contextual_precision(
    q, row.ideal_answer, ctx)
report(mean(recall), mean(precision))

14Golden-Dataset Guidance

  • Real user-like language & intent
  • Ideal answer > exact chunk IDs (survives re-chunking)
  • Generate in small batches, review manually
  • Expand w/ real production interactions over time
  • Treat suite as regression test — compare versions before release
