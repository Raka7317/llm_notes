01 • FUNDAMENTALS

What is a Knowledge Graph?

A Knowledge Graph (KG) is a structured representation of knowledge in which real-world entities are represented as nodes and the relationships between those entities are represented as edges.

Simple definition: A Knowledge Graph stores facts as connected entities and relationships, often represented as (Subject, Predicate, Object) triples.
Rakesh ── WORKS_AT ──▶ Google

Here:

  • Rakesh is an entity/node.
  • Google is an entity/node.
  • WORKS_AT is the relationship/edge.

03 • DATA MODEL

Knowledge Graph Triples

The most common conceptual representation is a triple:

Subject       Predicate          Object
------------------------------------------------
Rakesh        WORKS_AT           Google
Google        HEADQUARTERED_IN   California
Einstein      BORN_IN            Ulm
Einstein      DEVELOPED          Theory of Relativity
A triple can be read like a sentence: Subject → Relationship → Object.

Example

(Albert Einstein, BORN_IN, Ulm)

Subject   = Albert Einstein
Predicate = BORN_IN
Object    = Ulm

Multiple triples together create a connected graph rather than isolated facts.

04 • HOW DATA IS STORED

How does a Knowledge Graph store data?

Unlike a traditional relational database that mainly organizes data into tables and rows, a graph-oriented system emphasizes entities and their connections.

Conceptual storage

Node:
Rakesh
  type: Person

Node:
Google
  type: Organization

Node:
California
  type: Location

Relationship:
Rakesh --WORKS_AT--> Google

Relationship:
Google --HEADQUARTERED_IN--> California

Graph database vs RDF-style representation

Property Graph

Nodes and edges can both contain properties.

(Rakesh)-[WORKS_AT {
  role: "AI Engineer",
  since: 2025
}]->(Google)

Commonly associated with graph databases such as Neo4j.

RDF / Triple Store

Knowledge is naturally represented as subject-predicate-object statements.

<Rakesh>
  <WORKS_AT>
  <Google>

Often queried using SPARQL.

05 • FROM DOCUMENTS TO GRAPH

How is a Knowledge Graph created from text?

Suppose a document contains:

"Albert Einstein was born in Ulm, Germany in 1879.
He developed the theory of relativity."

An information-extraction pipeline identifies entities and relationships:

Raw Document
→
Entity Extraction
→
Relationship Extraction
→
Graph Construction

Step 1 — Entity extraction

Albert Einstein → PERSON
Ulm             → LOCATION
Germany         → LOCATION
1879            → DATE/YEAR
Theory of Relativity → CONCEPT

Step 2 — Relationship extraction

Albert Einstein → BORN_IN → Ulm
Albert Einstein → BORN_IN_YEAR → 1879
Albert Einstein → DEVELOPED → Theory of Relativity

Step 3 — Store the graph

Ulm
▲ BORN_IN
Albert Einstein ── DEVELOPED ──▶ Theory of Relativity
In modern AI systems, an LLM can help extract entities and relationships from unstructured documents, but the extracted facts should be validated before being treated as trusted knowledge.
06 • RETRIEVAL

How do we query a Knowledge Graph?

Graph traversal

Because relationships are explicit, we can follow paths through the graph.

Einstein
   │
   └── BORN_IN ──▶ Ulm

Question:

Where was Einstein born?

The system follows:

Albert Einstein
      ↓
    BORN_IN
      ↓
     Ulm

and can answer:

Albert Einstein was born in Ulm.

Multi-hop reasoning

Knowledge graphs become especially useful when the answer requires multiple relationships.

Einstein
   ↓ DEVELOPED
Theory of Relativity
   ↓ INFLUENCED
Modern Physics
   ↓ USED_IN
Cosmology

A query can traverse multiple hops to discover connected information.

Why Graph RAG?

  • Captures explicit relationships between entities.
  • Can support multi-hop questions.
  • Can connect information spread across multiple documents.
  • Can provide structured context to the LLM.
  • Can complement vector search instead of replacing it.
Important: A Knowledge Graph does not automatically make an LLM correct. Bad entity extraction, incorrect relationships, stale facts, or incomplete graph construction can still produce bad answers.
08 • BM25 VS KNOWLEDGE GRAPH

BM25 vs Knowledge Graph

BM25 and Knowledge Graphs solve different problems.

Aspect BM25 Knowledge Graph
What is it? Information retrieval / ranking algorithm Structured knowledge representation
Main purpose Find relevant documents or text Represent entities and relationships
Data view Text and terms Nodes and edges
Matching Primarily lexical / keyword-based Relationship and entity based
Strength Exact terms, names, identifiers Connected facts and multi-hop relationships
Typical use Search and first-stage retrieval Graph reasoning, structured retrieval, Graph RAG

Example

Query:

"Einstein born Ulm"

BM25: searches indexed text for matching terms such as Einstein, born, and Ulm.

Knowledge Graph: can directly represent:

Einstein ──BORN_IN──▶ Ulm

They can work together

User Query
→
BM25
+
Vector Search
+
Knowledge Graph
→
LLM
Key idea: BM25 retrieves relevant text; the Knowledge Graph represents and connects knowledge. They are complementary rather than direct replacements for each other.
09 • PRACTICAL USE

Advantages and Limitations

Advantages

  • Explicit relationships
  • Good for multi-hop reasoning
  • Structured representation
  • Entity-centric retrieval
  • Can combine facts from multiple sources
  • Useful for explainable paths

Limitations

  • Building the graph can be expensive
  • Entity resolution can be difficult
  • Relationship extraction can introduce errors
  • Graphs need maintenance and updates
  • Incomplete graphs can miss useful facts
  • Large graphs can require careful indexing and traversal strategies

Common use cases

  • Enterprise knowledge management
  • Recommendation systems
  • Search engines
  • Fraud detection
  • Drug and biomedical knowledge systems
  • Customer 360 systems
  • Question answering
  • Graph RAG
10 • INTERVIEW REVISION

Knowledge Graph — Interview Cheat Sheet

Q: What is a Knowledge Graph?
A Knowledge Graph represents knowledge as entities and relationships, commonly modeled as nodes, edges, and subject-predicate-object triples.
Q: What is a triple?
A triple consists of a Subject, Predicate, and Object. Example: (Einstein, BORN_IN, Ulm).
Q: How is it different from a vector database?
A vector database stores vector representations optimized for similarity search. A Knowledge Graph explicitly stores entities and their relationships.
Q: How is it different from BM25?
BM25 is a lexical retrieval/ranking algorithm. A Knowledge Graph is a structured representation of connected facts.
Q: Why use a Knowledge Graph in RAG?
It can improve entity-aware retrieval, relationship-aware retrieval, and multi-hop question answering by supplying structured connected context to the LLM.
