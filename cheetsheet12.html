7Build → Eval Flow

  1. Build retriever → evaluate it
  2. Build generator → evaluate it
  3. Connect into RAG pipeline → RAG Triad
  4. Evaluate app quality
  5. Evaluate app safety
  6. Evaluate operational metrics
Rule: evaluate continuously — never build everything first and test at the end.

8Retriever Basics

Load docs → chunk → embed → store in vector DB → query → retrieve top chunks.

9Retriever Metrics

Recall: of all relevant docs, how many were retrieved?
Precision: of all retrieved docs, how many were relevant?

10Generator (Isolated)

Evaluated alone, before connecting to retriever — question + context supplied via a golden dataset.

11Generator Metrics

  • Faithfulness — grounded in context, no hallucination
  • Answer Relevance — answers the actual question
  • Citation Accuracy — citations point to correct source

12RAG Triad

PairMetric
Question + ContextContext Relevance
Context + AnswerFaithfulness
Question + AnswerAnswer Relevance
RAG Triad = Context Relevance + Faithfulness + Answer Relevance

13Application — Quality

  • Correctness — is it right?
  • Completeness — covers every part of the question?
  • Style — matches desired tone/format?

14Application — Safety

  • Toxicity
  • PII Leakage
  • Jailbreak Resistance

16What Is an Eval Suite?

The full collection of tests — component + pipeline + application + safety + operations — run from one entry point (run_evals.py) for a repeatable report.

18DeepEval Library

Chosen library for this course — Pytest-style syntax, covers RAG + safety metrics, extends to agents/multi-turn/non-LLM/image apps.

Why not Ragas: already covered in advanced RAG course; DeepEval has broader scope.

19Tool-Agnostic Advice

Learn the concepts, not a specific tool — tools vary by company.

20Regression Testing

Run the full eval suite on a new version and compare against baseline: did metrics improve, decline, or stay the same? Should it deploy?

213 Levels of Regression Testing

SimpleManually compare new run vs baseline
Experiment TrackingLog configs & metrics, compare visually (MLflow, Confident AI, W&B)
CI/CDAuto-run evals on push, gate deployment by threshold

22CI/CD Gating Flow

Code change→Push→CI runs evals→Compare to baseline→Pass/Fail threshold→Deploy or Block

23Regression Core Idea

Evaluation = deployment gate. A regression beyond threshold blocks release.

24Online Evaluation

Monitoring continues after deployment via tracing tools: LangSmith, Langfuse, Confident AI.

LatencyCostTokensUser feedbackTracesDashboard

25Online Quality Metrics

  • Faithfulness (on live traffic)
  • Answer relevance (on live traffic)
  • Correctness / quality signals

26Drift Detection

Drift: performance changes/degrades over time — e.g. faithfulness dropping over last 24h → investigate.

27Self-Improving Loop

Live interaction→Failure found→Add to offline data→Future eval improves

28Interview Master Answer

  1. Build an Eval Suite
  2. Component: Recall, Precision
  3. Generator: Faithfulness, Answer Relevance, Citation Accuracy
  4. Pipeline: RAG Triad
  5. Application: Correctness, Completeness, Style
  6. Safety: Toxicity, PII, Jailbreak
  7. Ops: Latency, Cost, Tokens
  8. Regression vs baseline
  9. Experiment tracking / CI-CD gates
  10. Deploy only if criteria pass
  11. Online eval: traces, feedback, drift
  12. Feed failures back into golden dataset
